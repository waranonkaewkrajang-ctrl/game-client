## ข้อกำหนดจากผู้ใช้

1. มีทุกคู่ที่ต้นทางเปิดสตรีมอยู่ ให้คู่ใหม่เข้ามาเองและคู่จบออกเอง
2. ไม่เริ่มหาลิงก์ตอนลูกค้ากดคู่: selectMatch ใช้ URL ที่ได้รับล่วงหน้าอยู่แล้ว ห้ามใส่ fetch ใน handler นี้
3. ไม่แสดง “เตรียมสัญญาณ/เตรียมตัวเล่น” หรือรายละเอียด implementation บนหน้าลูกค้า
4. เมื่อคู่ที่กำลังดูจบ เปิดคู่สดถัดไปให้เองถ้าสวิตช์ auto เปิด; ไม่มีคู่ใหม่ให้รอ ไม่สร้างคู่ปลอม/รีเพลย์ติดป้ายสด
5. รายชื่อ/สกอร์ที่อัปเดตต้องไม่ reload iframe เดิมทุก 10 วินาที

## ต้นทางที่ตรวจพบจริง

- Live feed: https://api-streaming-channels.askmebet.live/matches-streaming-channel/soccer/live
- Detail: https://api-streaming-channels.askmebet.live/match/soccer/{matchId}
- URL player: https://askmebet.live/matches/{matchId}?uid={UUID-v4}
- JSON.data คืน HTTPS URL ของ GLIVE บน www.87333378.com path /livetv/...
- ห้าม hardcode URL session เต็มใน source/log/MD เพราะ path มี token/IP/timestamp
- ไม่แกะ media URL, ไม่ปลอม Origin/Referer และไม่มี proxy ไฟล์วิดีโอ วิดีโอโหลดตรงจาก iframe ผู้ให้บริการ

## สถานะและการสลับคู่

`live` → หายจาก feed ที่สำเร็จเป็น `checking` → หายอย่างน้อย 2 รอบพร้อมตรวจ detail → `ended` → เลือกคู่ live ถัดไปที่มี URL ใหม่

การยืนยันจบรองรับ FT/AET/ฯลฯ, results:null และรูปแบบที่เจอจริงเมื่อคู่โบลิเวียจบ: HTTP 200 `{ "message": "OK" }` โดยไม่มี results ไม่ใช้ HTTP error/JSON เสียเป็นเหตุสลับคู่

ข้อมูล live cache 10 วินาที ใช้ single-flight ป้องกันคำขอซ้ำ คิว URL ทำงานทุก 5 วินาทีขณะเปิดหน้า ครั้งละ 4 คู่, พร้อมกัน 2, รวมทุก session ไม่เกิน 4 ต่อ process ให้คู่ที่ยังไม่เคยขอลิงก์มาก่อนขึ้นก่อนการ refresh URL เดิม

เก็บ URL แยกผู้ชมด้วย cookie snake_live_viewer (HttpOnly, SameSite strict, path /api/live-football) ไม่เกี่ยวกับ token เข้าระบบ นโยบาย refresh URL ของเราคือ 90 วินาที ไม่ใช่อายุที่ต้นทางรับรอง การ refresh ไม่เปลี่ยน iframe ของคู่เดิมที่เล่นอยู่

## ผลที่ยืนยันและงานที่ยังต้องตรวจบนโฮสต์จริง

- เคยขอ URL ล่วงหน้า 2 คู่สำเร็จ ต่อมาคู่โบลิเวียจบ เหลือเม็กซิโก จึงไม่สามารถแสดง 2 คู่สดจริงตลอดเวลาได้ จำนวนขึ้นอยู่กับ feed
- iframe เล่นภาพจริง 960×540 ใน localhost:4179 และในหน้า /live ของ SNAKE168 เวลาเล่นเดินต่อเนื่อง และ iframe ไม่เปลี่ยนระหว่างอัปเดตข้อมูล
- TypeScript/ESLint และ tests 5 รายการผ่านในงานสร้างหน้า live; ทดสอบ responsive 1440/390/320px ไม่มี overflow
- ลิงก์อาจผูก IP/เซสชันตามรูปแบบที่พบ: ต้องทดสอบจาก production server กับผู้ชมอย่างน้อย 2 เครือข่ายก่อนอ้างว่าใช้จริงได้ทุกคน
- อย่าสรุปว่ามีพรีเมียร์ลีก/ทุกลีกครบจากการมีเมนูชื่อลีก เพราะทดสอบเฉพาะคู่ที่ feed เปิดจริง
- iframe ข้ามโดเมนทำให้ JS ของหน้าเราอ่าน video.ended/currentTime ไม่ได้ อย่าใช้ iframe onload ยืนยันว่าภาพเล่น หากจะใช้ postMessage ต้องมีเอกสาร events จริงจาก GLIVE
- cache/session/queue ยังเป็น process memory สำหรับหนึ่ง instance หากขยายหลายเครื่องต้องออกแบบ shared store/queue และ rate limit ตามผู้ให้บริการ
- ตรวจขอบเขตสิทธิ์ฝังวิดีโอตามสัญญาของผู้ให้บริการก่อนเผยแพร่ การมี AMBSuperAPI key ไม่ได้ยืนยันสิทธิ์ของ API วิดีโอแยกนี้โดยตัวมันเอง

- ตรวจจริง ESPN scoreboard รองรับ `?dates=YYYYMM&limit=1000`; รูปแบบช่วงวันที่ที่ลองตอบ 400 จึงใช้รูปแบบเดือนที่ยืนยันได้
- ดึง 5 รายการลีกคงที่: พรีเมียร์ลีก ลาลีกา เซเรียอา บุนเดสลีกา และ UCL; ไม่ถือว่าเป็นทุกลีกทั่วโลก หรือรับรองว่าตารางต้นทางครบทุกคู่

- หน้าเริ่มที่วันนี้เป็นต้นไป เลือกทั้งเดือน วันเฉพาะ และลีกได้ แสดงวันที่/เวลาไทย สถานะจริงของต้นทาง และรอยืนยันเวลาหาก timeValid ไม่ใช่ true

- API ESPN เป็น public endpoint ที่ทดสอบได้โดยไม่ใช้คีย์ ไม่ใช่สัญญา API ที่รับรองความพร้อมใช้ตลอด และไม่มีข้อมูลสิทธิ์ถ่ายทอดสดจาก endpoint นี้
- แสดงชื่อแหล่งตาราง ESPN ในหน้า ตรวจโลโก้ HTTPS เฉพาะ a.espncdn.com ไม่มีการติดตั้งแพ็กเกจ/แก้ Login/2FA/รีสตาร์ต

# หน้ารายการและหน้ารับชม — โครงอ้างอิง TESLA ปรับเป็น SNAKE168

- ตรวจหน้า `tesla68.co/home/live` และ `/sport-live/watch/2335914/1` จากหน้าจอจริง: รายการแถว / เรียงเวลา–ลีก / หน้ารับชมซ้ายและรายการขวา
- `/live` เปลี่ยนจากการ์ดเป็นแถว ทีม–โลโก้–เวลา–ปุ่ม มีแบนเนอร์ LIVE ที่สร้างด้วย SVG/CSS ของเรา ไม่ดึงภาพ โลโก้ ชื่อแบรนด์ JavaScript หรือ API คู่แข่ง
- หน้ารายคู่ใหม่ `/live/watch/[id]`: ใช้ numeric AMB ID หรือ URL `espn-{id}` ซึ่งแปลงกลับเป็น namespace `espn:{id}` ภายใน ตรวจรูปแบบ ID ก่อน render; รองรับลิงก์เก่าแบบ colon ด้วย
- `FixtureBrowser.tsx` รวมการแสดงผล ตาราง/ตัวกรอง/เรียงเวลาและลีก/ตัวเลือกเฉพาะ LIVE; ตารางของ ESPN ไม่แสดงปุ่มดูสดปลอม ใช้ “ดูรายละเอียด” เปิดหน้าคู่นั้น
- `MonthlyFixtures.tsx` ปรับเป็น `useMonthlyCalendar()` เพื่อให้ข้อมูลตารางรายเดือนใช้ทั้งสองหน้าได้ ไม่มีการเปลี่ยน endpoint เดิม
- เมื่อเปิดหน้ารับชมของ AMB ID ที่ live จริง หน้าอ่าน feed และคิว prepared เดิม แล้วเปิด URL ของ ID ที่เลือกเมื่อพร้อม; การเปลี่ยนคู่หลังจบยังใช้ chooseMatch และ auto switch เดิม ไม่มีการเปลี่ยน API/token หรือร้องขอ mint ใน click handler
- ESPN ID ไม่ใช่ AMB ID ปัจจุบันเพิ่ม mapping ที่ตรวจชื่ออังกฤษ/ลีก/เวลา/ประเภททีมและยืนยันสองรอบแล้ว ดู live-football-matching.md; หากยังไม่ยืนยัน หน้ารายคู่คงเป็นรายละเอียด/นับถอยหลัง
- `MatchPreview.tsx` ใช้ข้อมูลจริง สถานะและ timeConfirmed จาก API นับเวลาทุก 1 วินาที แยกเฉพาะ component ไม่ re-render iframe; เมื่อพ้นเวลาแต่ไม่มีสตรีม แสดงว่ายังไม่มีสัญญาณ ไม่สร้างสถานะ LIVE
- CSS module เขียนใหม่แทนชุดเก่า ปุ่มเต็มจอพื้นใสตามคำขอก่อนหน้า มือถือย้ายรายการคู่อื่นไว้ด้านล่าง บนคอมเป็น 2 คอลัมน์
- ตรวจ UI 1440/390/320px ไม่มี overflow, ตัวกรองพรีเมียร์ลีกทั้งเดือน 32 คู่, เปลี่ยนคู่จาก sidebar ผ่าน, fullscreen fallback ได้ 1440×1000 และออกได้
- ณ การตรวจรอบนี้ API live ว่าง จึงยังไม่ได้ยืนยันภาพวิดีโอสดซ้ำหลังเปลี่ยนดีไซน์; offline behavioral tests 7 รายการคงผ่าน
- ไม่ติดตั้งแพ็กเกจ ไม่ restart/commit/push ไม่เปลี่ยน Login/Register/2FA หรือ lib/api.ts (ตรวจ SHA256 ตรงก่อนเริ่มงาน)
